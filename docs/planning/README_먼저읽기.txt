# 프로젝트 문서 맵 — 먼저 읽기

이 문서는 팀원과 AI 어시스턴트가 프로젝트 맥락을 빠르게 잡기 위한 안내서다.
AI에게 작업을 시킬 때는 이 문서와 함께 필요한 문서를 첨부하면 된다.


================================================================
프로젝트 한 문단 요약
================================================================

팀명 태진아, 프로젝트명 밀리버릿(Mealiverit).
배달앱에서 매일 오전 11시에 오픈하는 선착순 할인 쿠폰을 소재로 한
동시성·정합성 백엔드 프로젝트다.

핵심 요구사항은 재고 10,000장에 20,000명이 동시 요청해도 초과발급 0건, 1인 최대 1매.
그리고 발급/사용/취소/만료 전 이력 300만 건에 대해 재고와 이력이 어긋나지 않음을
스스로 검증할 수 있어야 하며, 같은 데이터로 재실행하면 같은 결과가 나와야 한다.

기술 스택은 Java/Spring Boot + MySQL + Redis.
가게와 메뉴 데이터는 mocking이고, 프론트는 Claude Design으로 제작한다.
회원가입/로그인은 구현하지 않고 가상 회원 데이터를 사용한다.

조건: 팀원 6명, 개발 기간 2주, LG 부트캠프 멘토링 2회, 발표 및 시상 있음.
같은 주제로 4팀이 경쟁한다.

평가축 인식: 처리량과 응답속도는 평가 대상이 아니다.
평가되는 것은 동시성 정확성과 정합성 자기검증이다. 배점도 기술성+수행능력이 60%로
기획/브랜딩보다 우선한다.

현재 확정된 핵심 결정
================================================================

  - 기술 스택: Java + Spring Boot, MySQL, Redis (Docker Compose)
  - 동시성 전략: V1~V4 사다리를 전부 구현해 실측 비교 (03_버전사다리)
      V1 제어 없음 → V2 DB 비관적 락 → V3 Redis 게이트 → V4 Redis + DB 백스톱
  - API 경로: 실 서비스는 /api/v1 하나로 고정. 벤치마크는 /bench/{strategy}
  - DB 제약: uk_campaign_user, uk_idempotency_key, uk_coupon_code, version 컬럼
  - Redis 구성: 마스터 단일 노드 (복제 미사용. 배민 빼빼로데이 반례가 근거)
  - 멤버십: 4단계 등급(이등병/일병/상병/병장), 계급별 차등 할인율 10/30/50%
  - 취소 시 재고 복구: 하지 않음 (allow_reissue_on_cancel = false)
  - 프론트: 이벤트 페이지와 결제 페이지만 실제 동작. 나머지는 정적 mockup
  - 02_기능명세서_개정본 반영: coupon/coupon_issue에 max_discount_amount 컬럼 추가 필요(06_ERD 반영 대기),
      전체 FR이 G1/G2/G3 게이트로 매핑됨

AI에게 작업을 시킬 때 참고
================================================================

각 문서는 단독으로 읽어도 맥락이 잡히도록 상단에 배경 설명을 넣어두었다.
따라서 관련 문서 1~2개만 첨부해도 대화가 가능하다.

작업 유형별 첨부 권장:

  기능 범위·FR 확인      → 02, 00
  검증 쿼리 관련         → 05, 01
  동시성 구현 관련       → 04, 03
  일정/스코프 판단       → 07, 01
  발표 자료 작성         → 발표전략, 03, 리서치요약_쿠폰동시성사례

문서 간 내용이 충돌할 경우 우선순위:
  00_과제원문 > 01_설계보완_검토안 > 02_기능명세서_개정본 > 나머지
01이 기존 문서의 결함을 수정한 내역을 담고 있으므로, 검증 쿼리 등 세부 사항은 01을 우선한다.
02는 전체 FR을 통합한 최신 명세이지만, 01에서 이미 수정된 항목은 01의 버전을 따른다.

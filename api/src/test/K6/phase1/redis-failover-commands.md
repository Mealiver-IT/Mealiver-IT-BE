# Redis 장애주입 테스트 명령어 정리

Phase 3(Hardening)에서 "Redis가 죽어도 시스템이 자동으로 복구되는지" 라이브로 시연할 때 쓸 명령어 모음입니다.

## 사전 준비

Docker Compose로 Redis가 이미 떠 있다는 전제 (팀 문서 기준 인프라 구축 완료 상태).

Redis 컨테이너 이름/상태 확인:
```bash
docker ps
```
`docker ps` 결과에서 Redis 컨테이너 이름을 확인해두세요 (예: `mealivit-redis-1`, `redis` 등 docker-compose.yml 설정에 따라 다름). 아래 명령어의 `redis` 부분을 실제 컨테이너 이름으로 바꿔서 쓰면 됩니다.

---

## 시나리오 1 — 단순 재시작 (기본 장애 시연)

Redis를 강제로 재시작시켜서, 잠깐 응답이 안 되는 상황을 만듭니다.

```bash
docker restart redis
```

**시연 포인트:**
- 재시작 도중(몇 초간) 발급 요청이 어떻게 처리되는지 관찰
- 재시작 완료 후 시스템이 자동으로 정상 상태로 돌아오는지 확인
- 이 사이에 Redis-DB 불일치가 생겼다면, 보상 로직(재고 롤백)이 작동하는지 확인

---

## 시나리오 2 — 강제 중지 후 재시작 (더 긴 장애)

재시작보다 조금 더 긴 장애 상황을 흉내낼 때 사용합니다.

```bash
# 1. 중지
docker stop redis

# (여기서 몇 초~몇십 초 대기하며 시스템 반응 관찰)

# 2. 재시작
docker start redis
```

**시연 포인트:**
- Redis가 완전히 꺼진 동안 발급 API가 어떻게 실패 처리하는지 (에러 응답, 큐잉 등)
- 다시 켜졌을 때 카운터 값이 올바르게 복구되는지

---

## 시나리오 3 — 상태 확인 (장애 전후 비교용)

장애 전/후 Redis 안의 재고 카운터 값을 직접 확인할 때 사용합니다.

```bash
docker exec -it redis redis-cli GET stock:1:remaining
```
(`stock:1:remaining`은 캠페인 ID가 1인 경우의 예시 키 — 실제 키 네이밍 규칙에 맞게 수정)

전체 키 목록 확인:
```bash
docker exec -it redis redis-cli KEYS "*"
```

---

## 시연 흐름 제안 (발표용)

1. 정상 상태에서 부하테스트 진행 → 대시보드에 재고 숫자 줄어드는 거 보여주기
2. **`docker restart redis` 실행** (화면 공유하면서)
3. 잠깐 대시보드가 멈추거나 에러 표시되는 거 보여주기
4. Redis 재시작 완료되면 자동으로 다시 정상 작동하는 거 보여주기
5. 검증 배치 돌려서 "그 사이에도 초과발급/불일치 0건"이었다는 걸 리포트로 증명

## 주의사항

- 이 명령어들은 팀 컴퓨터(Docker Compose 띄운 곳)에서 실행해야 함 — 본인 로컬이 아니라 실제 DB/Redis가 있는 곳
- 라이브 데모 전에 반드시 리허설 한 번 해볼 것 (재시작에 걸리는 시간이 얼마나 되는지 미리 파악해두면 발표 타이밍 잡기 좋음)
- 컨테이너 이름은 `docker ps`로 반드시 사전에 확인 후 명령어에 반영
